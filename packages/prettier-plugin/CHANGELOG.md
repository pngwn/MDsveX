## 0.1.0-next.0

### Minor Changes

- [#1198](https://github.com/pngwn/MDsveX/pull/1198) [`cff2ff7`](https://github.com/pngwn/MDsveX/commit/cff2ff77658de45be2ae3bac6530af8b6c0acbad) Thanks [@pngwn](https://github.com/pngwn)! - New package: a Prettier plugin for mdsvex documents. It formats `.svx` and `.pfm` files, the Svelte in them as prettier-plugin-svelte formats a component and the markdown around it.

  ```json
  {
  	"plugins": ["@mdsvex/prettier-plugin"]
  }
  ```

  - A tag that does not fit on a line puts its attributes one to a line, and the children of elements, components and blocks such as `{#if}` are indented, markdown included. Scripts move to the top and styles to the end, and `svelteSortOrder` and `svelteIndentScriptAndStyle` work as they do for prettier-plugin-svelte.
  - The markdown is formatted as Prettier formats markdown, `-` bullets, ordered lists counted from their start, padded tables, a blank line between blocks and `proseWrap`, with emphasis kept as PFM writes it.
  - Frontmatter is formatted as yaml, imports, `<script>` and `<style>` as code, and expressions, attribute expressions, `{@html}`, `{@render}`, `{@const}`, `{@debug}` and the heads of blocks on one line. A part that does not parse is kept as written.
  - Code fences are kept as written, `mdsvexFormatFences` formats one whose info string is only a language Prettier knows.
  - Frontmatter a project parses itself with `frontmatter.parse` is kept, found from the manifest the vite plugin writes, and `mdsvexFrontmatter` sets it by hand.
  - `<!-- prettier-ignore -->`, `<!-- prettier-ignore-start -->` and `<!-- prettier-ignore-end -->` keep what they mark, and `<!-- @format -->` works with `--require-pragma` and `--insert-pragma`.
