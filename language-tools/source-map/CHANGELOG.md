# @mdsvex/source-map

## 0.1.0-next.2

### Minor Changes

- [#948](https://github.com/pngwn/MDsveX/pull/948) [`6c5901c`](https://github.com/pngwn/MDsveX/commit/6c5901c1eb87d10a2f43c835a10930a9dd5c0d27) Thanks [@pngwn](https://github.com/pngwn)! - The editor reads leaf and container directives written without square brackets. Args complete after `::toc(` and `:::Callout(`, and are checked and hovered as the props they become. The grammar highlights `::name` and `:::name(key=val)` when they are alone on their line, after any quote or list markers. An inline directive is still only highlighted and completed with its brackets.

- [#924](https://github.com/pngwn/MDsveX/pull/924) [`edaaa59`](https://github.com/pngwn/MDsveX/commit/edaaa59bda7e388248428eb7b6459442c7ddd216) Thanks [@github-actions](https://github.com/apps/github-actions)! - The editor knows the `plugin_data` export of a document. When the config has plugins, a document that reads `plugin_data` and a module that imports it type check against the `PluginData` interface, so a key a plugin declared has its type and any other is `unknown`. The manifest the Vite plugin writes says whether a plugin could leave data, and `mdsvex.config.json` says so with a `plugins` entry.

- [#1135](https://github.com/pngwn/MDsveX/pull/1135) [`56c5c71`](https://github.com/pngwn/MDsveX/commit/56c5c71c9184b7a9362ac39bd3bbaee5412813b4) Thanks [@pngwn](https://github.com/pngwn)! - Footnote references and definitions are highlighted. A reference with no definition and a label defined twice are reported where they are written, and the rest of the document keeps working. A definition nothing refers to is a warning.

- [#945](https://github.com/pngwn/MDsveX/pull/945) [`50e0b8c`](https://github.com/pngwn/MDsveX/commit/50e0b8ccc97885e0ca7eed53c075bfaed7969b23) Thanks [@pngwn](https://github.com/pngwn)! - The editor compiles `math` fences as the Vite plugin does, so a `math` replacement is type-checked with the props the build gives it. It reads the option from the manifest the plugin writes, and `mdsvex.config.json` takes `math`. With Temml, LaTeX that can't be rendered is reported at its place in the fence and the rest of the document keeps working. With KaTeX or a renderer function the LaTeX isn't checked.

### Patch Changes

- [#1224](https://github.com/pngwn/MDsveX/pull/1224) [`548f7c4`](https://github.com/pngwn/MDsveX/commit/548f7c4b57624646be0456dc6347a37fbcdcf114) Thanks [@pngwn](https://github.com/pngwn)! - The type declarations write `.js` on their relative imports, so they resolve under `moduleResolution: node16` and `nodenext` as well as `bundler`. A project on `node16` or `nodenext` used to get TS2834 errors from inside the packages, or with `skipLibCheck` on, `any` where the types should be.

- [#1042](https://github.com/pngwn/MDsveX/pull/1042) [`364b172`](https://github.com/pngwn/MDsveX/commit/364b17205ef9a73e0fb037b7da0b217018cc097d) Thanks [@pngwn](https://github.com/pngwn)! - A fence that shows a file with `src=` is no error in the editor, which reads no files and shows the fence empty. A fence with `src=` and code of its own is reported at the fence.

- [#1115](https://github.com/pngwn/MDsveX/pull/1115) [`89bf377`](https://github.com/pngwn/MDsveX/commit/89bf3776a22003ab42517b9b8a542507fce6f03b) Thanks [@pngwn](https://github.com/pngwn)! - The editor shows a fence marked `run` as code, with no import for TypeScript to report. The code of the block is not checked as a module.

- [#1216](https://github.com/pngwn/MDsveX/pull/1216) [`6a5ea43`](https://github.com/pngwn/MDsveX/commit/6a5ea43e8614d3ca370132d1af4def079c8cf926) Thanks [@pngwn](https://github.com/pngwn)! - The editor checks the props markdown gives a replacement component against the props it takes. A `src` the component does not accept is reported at the destination of the image, an `alt` at its text, a `level` at the heading marker and an `href` at the destination of the link, or at the whole link or image when it is a reference. A prop the component does not declare is not reported, as for HTML it replaces.

- [#1139](https://github.com/pngwn/MDsveX/pull/1139) [`7dfb9c9`](https://github.com/pngwn/MDsveX/commit/7dfb9c9c7301e96e4780c03ff45b04dbee6e92c4) Thanks [@pngwn](https://github.com/pngwn)! - The editor reports a code block marked `run` that the build would reject, at its fence: a language no block runs in, `run` beside `eval`, a `run=` value other than `client`, and, when the config is known, a block that runs with no component replacing `pre`.

- [#1214](https://github.com/pngwn/MDsveX/pull/1214) [`b28cc8f`](https://github.com/pngwn/MDsveX/commit/b28cc8fae9fae6dd96cbe9cd5e5b4e72c7df4a22) Thanks [@pngwn](https://github.com/pngwn)! - The packages publish JavaScript with type declarations, so they import from Node. Their entries were TypeScript source, which only a bundler that compiles TypeScript could load. Their types come from `mdsvex/compile`, so checking them needs no Vite.

  `@mdsvex/language-server` exports `start()`, which starts the server on the connection the process was given. Importing the package starts nothing. The `pfm-language-server` command runs the built server directly.

- [#1140](https://github.com/pngwn/MDsveX/pull/1140) [`1cb7ec9`](https://github.com/pngwn/MDsveX/commit/1cb7ec95e846f268693dee42dc8ab4ea013de368) Thanks [@pngwn](https://github.com/pngwn)! - The packages hold only what they run. Tests, fixtures, build config and intermediate build output are no longer published, which takes `@mdsvex/parse` from 2,337 files to 28.

- [#939](https://github.com/pngwn/MDsveX/pull/939) [`3ca3b52`](https://github.com/pngwn/MDsveX/commit/3ca3b525050c5874ac9ff7130033fe00d0112cba) Thanks [@pngwn](https://github.com/pngwn)! - The editor compiles a document with `unwrap_images` when the Vite plugin has it on, so an image replacement is type-checked where the build renders it. The plugin writes the option to its manifest, and `mdsvex.config.json` takes `unwrap_images: true`.

## 0.1.0-next.1

### Minor Changes

- [#887](https://github.com/pngwn/MDsveX/pull/887) [`ffaf805`](https://github.com/pngwn/MDsveX/commit/ffaf805cd7ac2ebb07c1b5a33896c36e53dc6c67) Thanks [@pngwn](https://github.com/pngwn)! - The editor now knows your templates, replacement components and directives. The Vite plugin writes what it resolved to `node_modules/.mdsvex/manifest.json` and the editor reads it, falling back to an `mdsvex.config.json` like the playground's:

  ```json
  {
  	"templates": { "docs": "#lib/templates/Docs.svelte" },
  	"components": "#lib/markdown.ts"
  }
  ```

  Hovering a replaced element or directive shows its component, and go to definition opens it. The frontmatter `template` key is typed as your template names or `false`. Completions offer template names, the template's props as frontmatter keys and their literal values, and a directive's props as args with their values. Directive args and the frontmatter of a templated document are type-checked against the component's props, and `metadata` is typed by the same YAML parser `compile()` uses. Compile errors such as an unknown template show on their line, and `.svx` files are supported alongside `.pfm`.

- [#895](https://github.com/pngwn/MDsveX/pull/895) [`57ecb44`](https://github.com/pngwn/MDsveX/commit/57ecb446b292a3406dcf62550986ed15e1aa2b80) Thanks [@pngwn](https://github.com/pngwn)! - The editor reads live expressions in code as references, so type errors, hover, rename and the unused check work on them. It highlights code as the Vite plugin does unless the plugin renders code plain, and `mdsvex.config.json` takes `highlight: false`. A half-typed live expression is an error on that fence rather than on the whole document.
